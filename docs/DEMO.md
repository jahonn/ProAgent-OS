# Mock demo

Offline path. No API key and no network call to a model. The script forces `PROAGENT_LLM_PROVIDER=mock` when that variable is unset, writes a gitignored SQLite file, and prints each stage.

Identifiers (`ten_…`, `task_…`, `mon_…`, `rec_…`, `out_…`, `mem_…`) change every run. The titles, plan, mock answer, skill list, and agent list below are stable on the current fixtures.

What was recorded, with `PROAGENT_LLM_PROVIDER=mock`, no API key, and no model network call:

```bash
python scripts/demo.py

```

`scripts/demo.py` is the full path: tenant, knowledge base, task, monitor, noop executor, outcome. The support-desk script is the shorter second beat (policy search, `ticket_triage`, and a follow-up the noop executor marks executed without sending a reply).

Lines longer than 100 columns are wrapped on spaces so the frame stays readable. The words are the scripts' stdout. Identifiers change when the recording is regenerated.

Re-record from the repo root after the install in [Setup](#setup):

```bash
python scripts/record_demo.py
```

That overwrites `docs/demo.cast` and `docs/demo.svg`. Child processes force the mock provider, drop provider credentials, and use a temporary SQLite file. No database is committed.

## Setup

From a fresh clone:

```bash
git clone https://github.com/jahonn/ProAgent-OS.git
cd ProAgent-OS
python3 -m venv .venv
source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pip install -e .
```

Python 3.11 or newer. The demo needs the install above; it does not need Docker or a `.env` file.

## Run the script

```bash
python scripts/demo.py
```

That command is the first half of the recording in [Watch it first](#watch-it-first). `python scripts/record_demo.py` runs it again, then `python scripts/demo_support_desk.py`, and refreshes `docs/demo.cast` and `docs/demo.svg`.

What the script sets for you (only if the variable is unset):

| Variable | Value |
|----------|--------|
| `PROAGENT_DB_PATH` | `./data/demo.db` |
| `PROAGENT_ADMIN_KEY` | `dev-admin-key` |
| `PROAGENT_LLM_PROVIDER` | `mock` |
| `PROAGENT_AGENTS_CONFIG` | `./config/agents.yaml` |
| `PROAGENT_SKILLS_DIRS` | `./skills`, `./verticals/example/skills`, and `./verticals/support_desk/skills` |

If `PROAGENT_DB_PATH` is already exported, the script uses that file and deletes it first. Leave it unset to keep the demo database separate from `./data/proagent.db`.

## What you should see

The process exits 0 and prints six stages plus a dashboard.

1. **Tenant.** `Acme Analytics`, goals about raising trial-to-paid conversion to 2.5%, tone "confident and concise". API key `pk_demo_acme_analytics`.
2. **Knowledge base.** Two documents: `Acme Analytics Platform Overview` (1 chunk, from `fixture://sample_product.html`) and `sample_notes` (1 chunk, from `fixtures/sample_notes.md`). Search for `conversion rate` returns 1 hit. On the default BM25 path the top score is `1.4492`.
3. **Task.** Status `completed`. Plan steps are `researcher` then `analyst`. The result is the mock aggregator text and ends with `_Generated by MockLLM for offline demo._`
4. **Monitor.** A `metric_stub` monitor named `Conversion watch` emits a recommendation titled `Conversion below 2.5% target`.
5. **Decision.** That recommendation's status becomes `executed`. The default executor is `noop`: it records the decision and an execution audit row, and it does not call the network. Set `PROAGENT_EXECUTOR_MODE=off` if approve should stay `approved`.
6. **Outcome.** Metric `conversion_lift_pp` value `0.4`. Learning feedback is positive. Skill `market_scan` weight becomes `1.05` with `updates: 1`.

Dashboard shape (counts, not ids):

- `tasks`: one row, `status` `completed`, `n` `1`
- `acceptance.counts`: `executed` `1` and `pending` `1`
- `acceptance.acceptance_rate`: `1.0`, `decided`: `1`
- `outcomes.by_metric`: `conversion_lift_pp`, `n` `1`, `avg_value` `0.4`
- `skills`: `analyst`, `research`, `market_scan`, `policy_lookup`, `ticket_triage`
- `agents`: `planner`, `researcher`, `analyst`, `aggregator`, `market_scout`, `support_triage`

The pending recommendation is expected. During the task the analyst calls `emit_recommendation`, which stays `pending`. The acceptance rate ignores pending items and only counts decided ones, so the executed monitor recommendation reports `1.0`.

## Open the console on the demo database

`data/demo.db` holds the tenant. Point the API at that file or the key will not match.

```bash
export PROAGENT_ADMIN_KEY=dev-admin-key
export PROAGENT_LLM_PROVIDER=mock
export PROAGENT_DB_PATH=./data/demo.db
uvicorn proagent_os.main:app --host 0.0.0.0 --port 8080
```

- http://localhost:8080 — header **ProAgent OS**, badge `v0.1.0`, sidebar tabs Task console, Knowledge base, Recommendations, Skills, Monitors, Dashboard. Paste `pk_demo_acme_analytics` and choose **Save key**.
- http://localhost:8080/health — `{"status":"ok","version":"0.1.0","llm":"mock"}` when the provider is mock.
- http://localhost:8080/docs — FastAPI reference for `/api/v1/*`.

Recommendations for this tenant: one `executed` (the monitor, via the noop executor) and one `pending` (the analyst tool call). The dashboard tab shows the same outcome metric as the script.

Optional worker, same environment so it shares the file:

```bash
python -m proagent_os.worker
```

## Fresh API database

Skip the demo file when you want an empty app:

```bash
export PROAGENT_ADMIN_KEY=dev-admin-key
export PROAGENT_LLM_PROVIDER=mock
export PROAGENT_DB_PATH=./data/proagent.db
uvicorn proagent_os.main:app --host 0.0.0.0 --port 8080
```

```bash
curl -s -X POST http://localhost:8080/api/v1/tenants \
  -H "Authorization: Bearer dev-admin-key" \
  -H "Content-Type: application/json" \
  -d '{"name":"Acme","goals":"Grow conversion","tone":"concise"}'
```

The JSON includes a new `api_key`. Use that bearer token for tenant routes. `dev-admin-key` can list tenants; it is the bootstrap admin key from the environment, not a tenant key.

Docker Compose (`docker compose up --build`) also starts from an empty volume. Create a tenant the same way. It does not mount `data/demo.db`.

## Troubleshooting

Common issues when running the mock demo or starting the API for the first time.

### Forgot to activate the virtual environment / wrong Python

If `python` or `pip` commands fail with module-not-found errors, or the version is older than 3.11:

```bash
source .venv/bin/activate   # Windows: .venv\Scripts\activate
python --version            # should be 3.11+
```

Re-run `pip install -r requirements.txt` and `pip install -e .` after activating. See the [Setup](#setup) section.

### Port 8080 already in use

When starting uvicorn:

```bash
uvicorn proagent_os.main:app --reload --port 8080
```

you may see `Address already in use`. Free the port or pick another:

```bash
# find and stop the process using 8080, or
uvicorn proagent_os.main:app --reload --port 8081
```

### Fresh database vs demo database

`python scripts/demo.py` writes to `./data/demo.db` (gitignored) when `PROAGENT_DB_PATH` is unset. If you already have a database or want a clean start:

- Unset or remove `PROAGENT_DB_PATH` so the script uses `./data/demo.db` and deletes it first.
- Or explicitly set `PROAGENT_DB_PATH=./data/demo.db` after the script runs, then start the API against that file so the demo tenant key `pk_demo_acme_analytics` works.
- For a completely empty app, use `PROAGENT_DB_PATH=./data/proagent.db` and create a tenant (see [Fresh API database](#fresh-api-database)).

See the environment table in the [root README](../README.md#environment-variables).

### OpenAI provider without an API key

Setting `PROAGENT_LLM_PROVIDER=openai` without `PROAGENT_LLM_API_KEY` causes the provider to fall back to mock (or fail depending on configuration). For the offline demo leave the provider unset or set it to `mock`. Real keys belong only in your local `.env` or shell; never commit them.

### Rate limit 429 during local testing

Heavy local curling of `/api/v1` can hit the in-process rate limiter (default 120 requests / 60 s). Raise the limits or disable temporarily:

```bash
export PROAGENT_RATE_LIMIT_REQUESTS=1000
export PROAGENT_RATE_LIMIT_WINDOW_SECONDS=60
# or
export PROAGENT_RATE_LIMIT_ENABLED=false
```

See `PROAGENT_RATE_LIMIT_*` in the [environment variables table](../README.md#environment-variables).
