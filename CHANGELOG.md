## [Unreleased]

### Added

- Optional LLM session-compaction summarizer. `PROAGENT_COMPACTION_SUMMARIZER=extractive` (default) stays the offline join/truncate stub. `llm` summarizes older turns with the configured chat provider (mock returns a deterministic summary; `openai` uses the OpenAI-compatible client) and, on failure, falls back to extractive with `summarizer_mode` / `summarizer_fallback` on the summary meta and the `compaction` trace. Keep-last-N and tool-pair rules are unchanged. See [docs/MEMORY.md](docs/MEMORY.md).
- HITL approve executes the paused gated tool, then continues the run. A tool with `requires_human_approval` pauses with a structured `pending_action` snapshot (`kind=gated_tool`, tool name, call id, schema-validated `arguments`, opaque `proposed`). `POST /api/v1/tasks/{id}/resume` re-invokes that tool once through `ToolRegistry` (schema checked again; only if the tool still requires approval and the snapshot matches the checkpoint), records the observation, and finishes remaining plan steps. `PROAGENT_HITL_EXECUTE_ON_APPROVE` defaults to true; set false to continue without running the tool. The legacy continue-off stub does not run it. Reject cancels and never executes. Snapshots are not URLs or shell commands. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) and [docs/TOOLS.md](docs/TOOLS.md).

## [0.1.1] - 2026-11-02

First public GitHub Release. `pyproject.toml` and `proagent_os.__version__` are `0.1.1`.

### Docs

- Human release notes for this release: [docs/RELEASE_NOTES_v0.1.1.md](docs/RELEASE_NOTES_v0.1.1.md).

### Added

- HITL mid-loop resume after approve. Orchestrator pauses store a durable `hitl_checkpoint_json` (migration `0006_hitl_checkpoint`: plan, completed steps, pause locus). `POST /api/v1/tasks/{id}/resume` re-enters the paused specialist with the human decision injected, runs remaining plan steps, and aggregates — shaped like OpenAI Agents `RunState.approve` / LangGraph `Command(resume=...)`. Default `PROAGENT_HITL_RESUME_CONTINUE=true`; set `false` for the legacy mark-completed stub. Reject/cancel never continue. Manual `POST .../pause` without a checkpoint still stub-completes on resume. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
- Plan-and-replan outer loop stub. After specialist steps, optional `PROAGENT_REPLAN_ENABLED` (default **false**, zero behavior change) may re-call the planner with prior plan + observations when triggers fire (empty plan, empty step results / aggregate inputs, all steps failed, or `PROAGENT_REPLAN_FORCE` for fixtures). Capped by `PROAGENT_REPLAN_MAX` (default 1). Trace phase `replan` (`LoopPhase.REPLAN`). Inner ReAct tool loop unchanged. Heuristic only — not an LLM sufficiency judge / DAG replanning / cost budgets. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
- Tool schema hardening. `ToolRegistry.invoke` validates arguments against each tool's JSON schema (stdlib subset in `proagent_os/professional/tools/validation.py`) before `run`, matching OpenAI FunctionTool / Anthropic tool_use. Failures return a structured observation (`schema_validation_failed`) and never execute (no HTTP/file). `PROAGENT_TOOL_SCHEMA_STRICT` defaults to `true`. HITL tools validate before pause. See [docs/TOOLS.md](docs/TOOLS.md).
- Session / context compaction stub. `ConversationMemory` folds older turns into a `summary` message when over `PROAGENT_COMPACTION_MAX_MESSAGES` / `MAX_CHARS`, keeps system + last N raw (tool pairs prefer not to split), and records auditable meta + `tenant_memory` kind=`compaction`. Default summarizer is extractive (no live LLM; inject `Summarizer`). Orchestrator injects a prior-context block and may emit trace phase `compaction`. See [docs/MEMORY.md](docs/MEMORY.md) and [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
- Task-run HITL pause/resume stub. Migration `0005_task_hitl_pause` adds `pause_reason`, `pending_action_json`, `hitl_decision`, `hitl_decided_at` on `tasks`. Status machine: `running` → `awaiting_human` → `completed` (resume) or `cancelled` (reject). Builtin tool `request_run_approval` (`requires_human_approval`) pauses the orchestrator cleanly; `POST /api/v1/tasks/{id}/pause|resume|reject` reuses `recommendation.decide` RBAC. Original stub marked completed without re-entering; superseded by mid-loop resume above when the continue flag is on. `pending_action_json` is opaque JSON — never a URL or shell command. Proactive `emit_recommendation` path unchanged. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
- Golden-task / tool-trajectory evaluation stub. `proagent_os/eval/` loads JSON fixtures from `tests/fixtures/eval/`, compares `tool_trajectory(trace)` with **ordered_subset** matching (extras allowed; no LLM judge), and returns structured pass/fail + diffs. Mock Orchestrator pytest in `tests/test_eval_golden.py`. Metering hook is a no-write stub until an `eval_run` usage kind exists. See [docs/EVAL.md](docs/EVAL.md).
- Explicit agent-loop phases and architecture docs. `LoopPhase` / `event()` in `proagent_os/harness/loop.py` stabilize plan → specialist → tool → aggregate trace labels; `tool_trajectory` and `summarize_run` are trajectory **stubs** (not LLM judges). Orchestrator writes phases through those helpers. See [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) for the OpenAI / Anthropic / LangGraph / ADK / ReAct mapping. Mock LLM path unchanged.
- OAuth/SSO and RBAC sketch. Default `PROAGENT_AUTH_MODE=api_key` is unchanged: the admin key is role `admin`, and a tenant API key is `tenant_operator` unless `PUT /api/v1/tenants/{id}/role` stores `tenant_readonly` (migration `0004_tenant_role_overrides`). `tenant_readonly` can read recommendations and usage and cannot approve, reject, execute, or rotate/revoke its key. Other tenant write routes are not gated yet. `PROAGENT_AUTH_MODE=oidc` fails startup (API and worker) until `PROAGENT_OIDC_ISSUER`, `PROAGENT_OIDC_AUDIENCE`, and `PROAGENT_OIDC_CLIENT_ID` are set. That mode does not call an identity provider, does not read a client secret, and still accepts the admin key and tenant API keys. JWTs are accepted only through a process-local `TokenVerifier`; `HmacJwksVerifier` is an in-memory HS256 test double, not a JWKS fetch. See [docs/AUTH.md](docs/AUTH.md).
- Optional OpenTelemetry hooks. `proagent_os/observability.py` is a no-op unless `PROAGENT_OTEL_ENABLED=true` and the `otel` extra is installed (`pip install 'proagent-os[otel]'`). Spans cover the HTTP request, KB search, recommendation approve/execute, and the LLM chat call. The SDK is imported only when the flag is on. A missing package logs a warning and leaves spans as no-ops. `PROAGENT_OTEL_EXPORTER` is `console` (demo), `otlp` (optional `PROAGENT_OTEL_EXPORTER_OTLP_ENDPOINT`), or `none`.
- Usage metering stub. Migration `0003_usage_events` appends a SQLite `usage_events` table (`tenant_id`, `kind`, `quantity`, `created_at`) for `llm_tokens`, `kb_search`, and `recommendation_execute`. `GET /api/v1/usage` returns aggregated counts for the tenant bearer, or for every tenant (or one `tenant_id`) with the admin key. The payload is labeled `billing: stub`. There is no payment provider and no charge.
- SQLite schema migrations. Startup (and `python -m proagent_os.migrations`) records versions in `schema_migrations` and applies pending steps in order. Version `0001_baseline` is the previous `CREATE TABLE IF NOT EXISTS` schema, including `tenants.key_status`. A database that already has that schema is stamped at version 1 and the baseline script is not run again. Version `0002_tenant_list_indexes` adds indexes on `tasks`, `kb_chunks`, and `recommendations`. sqlite-vec virtual tables stay on demand and are not part of these steps. Backup and restore are documented in `docs/DATABASE.md`.
- OpenAI-compatible knowledge-base embeddings. `PROAGENT_KB_EMBED_BACKEND=openai` POSTs to `{base}/embeddings`, reusing `PROAGENT_LLM_BASE_URL` and `PROAGENT_LLM_API_KEY` unless `PROAGENT_KB_EMBED_BASE_URL` or `PROAGENT_KB_EMBED_API_KEY` is set. `PROAGENT_KB_EMBED_MODEL` (default `text-embedding-3-small`) and `PROAGENT_KB_EMBED_DIMS` are sent as `model` and `dimensions`. The default backend remains `stub` and the default search mode remains BM25, so CI stays offline. A missing key, a missing base URL, or a failed call raises, and the KB HTTP routes return 503. pgvector is not wired.
- Optional sqlite-vec knowledge-base index. `PROAGENT_KB_VECTOR_STORE=sqlite_vec` (install `pip install 'proagent-os[vec]'`, `sqlite-vec>=0.1.9`) stores chunk vectors in a `vec0` table and runs hybrid/vector KNN in the extension. The default remains `blob`: float32 rows in `kb_chunk_embeddings` and cosine in Python. BM25 never loads sqlite-vec. A missing package or an extension that fails to load raises `VectorStoreConfigError` (HTTP 503) instead of silently using the blob path. CI does not install the extra; the extension test skips when it cannot load. pgvector is still not wired.
- Recorded mock demo: `docs/demo.svg` (SMIL terminal animation) and `docs/demo.cast` (asciinema v2), captured from `scripts/demo.py` and a short `scripts/demo_support_desk.py` beat with `PROAGENT_LLM_PROVIDER=mock`. Regenerate with `python scripts/record_demo.py`.
- Tenant API keys can be rotated and revoked. `POST /api/v1/tenants/me/api-key/rotate` and `.../revoke` use the tenant bearer. Admin uses `POST /api/v1/tenants/{tenant_id}/api-key/rotate` and `.../revoke`. Rotate is a hard cutover (no grace window). A revoked key returns 401 until an admin rotate mints a replacement. `tenant_api_key_audit` stores a prefix and SHA-256, not the raw key. Existing databases gain `tenants.key_status` on startup.
- In-process fixed-window rate limit on `/api/v1` (`PROAGENT_RATE_LIMIT_ENABLED`, `PROAGENT_RATE_LIMIT_REQUESTS`, `PROAGENT_RATE_LIMIT_WINDOW_SECONDS`). Over the limit the response is HTTP 429 `{"detail":"Rate limit exceeded"}` with `Retry-After`. No Redis. Counters are per process.
- Recommendation executors: `off`, `noop` (default), and `webhook`. Approve writes `recommendation_audit` (`decided`, `executed`, `execute_failed`). Webhook POSTs only to `PROAGENT_EXECUTOR_WEBHOOK_URL`; the action payload is JSON, not a URL or command. The mock demo marks the monitor recommendation executed without network.
- Support desk vertical (`verticals/support_desk/`): sample policies, `support_triage`, `ticket_triage` and `policy_lookup` skills, and `scripts/demo_support_desk.py`. Startup merges every `verticals/*/agents/agents.yaml`. The support demo approves through the default noop executor.
- README scan path for first-time visitors: one-line product description, who it is for, a positioning table, and a harness architecture diagram.
- Scripted mock-demo notes in `docs/DEMO.md` (commands and the output to expect). No API key required.

## [0.1.0] - 2026-10-29

First public MVP. `pyproject.toml` and `proagent_os.__version__` are `0.1.0`. Early open source: demos, vertical scaffolding, and self-hosted experiments.

### Added

- Agent harness: planner → specialists → aggregator, YAML agent registry, SQLite task and trace memory.
- Commercial surface: FastAPI `/api/v1`, one Bearer API key per tenant, a small web console, and Docker Compose (`api` + `worker` on a shared SQLite volume).
- Private knowledge base: URL/HTML and file ingest (md/txt/html, PDF best-effort), per-tenant BM25 search, brand context, and skill packs. Built-in tools: `http_fetch`, `file_read`, `kb_search`, `clock`, `emit_recommendation`.
- Proactive monitors (`kb_change`, `metric_stub`, `data_source`) that write a recommendation inbox. Approve and reject update status. They do not execute the proposed action.
- Outcome loop: `record_outcome`, tenant-memory feedback, and a simple skill-weight nudge (not a trained policy).
- Native OpenAI-style tool calling with a multi-round specialist loop, plus a JSON-in-content fallback. Planner and aggregator stay text-only. `PROAGENT_LLM_PROVIDER=mock` runs with no API key.
- GitHub Actions CI: `pytest` on Python 3.11 and 3.12 with the mock LLM, and a pull request template.
- Optional `hybrid` and `vector` retrieval using an offline hash-bag stub embedder (`PROAGENT_KB_EMBED_BACKEND=stub`). Default search remains BM25, which is what CI runs. sqlite-vec, pgvector, and remote embedding providers are not wired; the `vec` extra is a placeholder.
